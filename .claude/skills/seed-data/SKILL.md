# Генерация синтетических данных

Скрипт: `backend/scripts/seed.py`. Запуск: `cd backend && python -m scripts.seed --reset`.
Генератор: `numpy.random.default_rng(42)`. Два запуска обязаны давать одинаковые данные.

## Объём

- 1 предмет: «Математика»
- 12 тем, 3 учебника (A, B, C)
- 5 школ, 4–5 классов в школе (22 класса), 23–27 учеников в классе (около 560)
- 2 теста на тему, 3% случайных пропусков: около 13 000 результатов
- Имена только обезличенные: «Школа №1», «Ученик 001»

## Школы и учебники

Учебник назначается классу, и в каждой школе есть все три.
Это обязательно: z-нормализация идёт внутри школы, и если бы вся школа училась
по одному учебнику, разница между учебниками обнулилась бы.

Сильные школы чаще выбирают C. Это заложенное смешение: по сырому среднему C выше A
примерно на 4 балла, а при сравнении внутри школы и в регрессии разница около 0
(кроме геометрии). На этом построен главный момент демо.

| Школа | Уровень | Классы (6А, 6Б, …) |
|---|---|---|
| №1 | −8 | A, A, B, C |
| №2 | −4 | A, B, B, C |
| №3 | 0 | A, B, C, C |
| №4 | +4 | A, B, C, C, C |
| №5 | +8 | A, B, C, C, C |

Итого классов: A 6, B 6, C 10.

## Модель балла

`score = clip(round(база_темы + школа + класс + ученик + учебник + освоение + зависимость + шум), 0, 100)`

| Компонент | Значение |
|---|---|
| школа | уровень из таблицы выше |
| класс | N(0, 2), одно значение на класс |
| ученик | N(0, 10), одно значение на все темы |
| освоение | `m ~ N(0, 8)`, одно значение на ученика и тему, оба теста темы |
| зависимость | `коэффициент × m` ученика по теме-основе, только у зависимых тем (таблица ниже) |
| шум | N(0, 8), на каждый результат |
| учебник A | 0 |
| учебник B | −8 в «Дроби» и «Проценты», −3 в остальных темах |
| учебник C | +1, а в «Геометрические фигуры» и «Площадь и объём» +5 |

Система должна показать слабое место B, сильную сторону C и пары учебников без значимой разницы.

## Зависимости тем

Пробел в теме-основе переносится в балл зависимой темы. Это то, что находит `/topics/prerequisites`.

| Тема-основа | Зависимая тема | Коэффициент |
|---|---|---|
| Дроби | Проценты | 0.6 |
| Дроби | Десятичные дроби | 0.5 |
| Отрицательные числа | Уравнения | 0.6 |

Разброс освоения 8, а не 6: при 6 на seed 42 связь «Дроби → Проценты» слабее порога метрики (0,14 < 0,15),
при 8 все три связи находятся на 12 из 12 проверенных seed, а без зависимостей лишних связей нет.
`generate(session, prerequisites={})` создаёт те же данные без зависимостей: меняются только баллы
трёх зависимых тем. Так тесты проверяют, что метрика не находит связей там, где их нет.

Аномалия: в классе 6Д Школы №4 тема «Отрицательные числа» на 12 баллов ниже модели
(пропущенная тема или смена учителя). Её находит `/classes/outliers`.

## Дополнительные данные

Создаются отдельными генераторами (`seed + 1…5`), поэтому основные баллы от них не зависят.
Освоение тем (`seed + 5`) меняет баллы, но не сдвигает последовательность основного генератора.

| Данные | Модель |
|---|---|
| Задания | 8 на тест, сложность `b ~ N(0, 0.8)`, среднее по тесту 0 |
| Ответ на задание | вероятность верного `logistic(θ − b)`; `θ = среднее_теста + 2 × (logit(балл/100) − среднее_теста) + сдвиг`, балл ограничен 3–97; сдвиг подобран для каждого теста так, чтобы средняя доля верных равнялась среднему баллу |
| Плохие задания | «Дроби», тест 1, задание 3; «Уравнения», тест 2, задание 5: вероятность 0.5 у всех |
| Входной тест | `clip(round(65 + школа + ученик + N(0, 6)), 0, 100)` |
| Архив | 2022–2025, среднее школы по теме: `текущее − тренд × (2026 − год) + N(0, 1)` |
| Тренд в год | «Дроби» −1.5, «Геометрические фигуры» +1.2, остальные темы 0 |

`python -m scripts.seed --if-outdated` пересоздаёт БД, если в ней нет таблиц или столбцов текущих моделей
или версия данных (`PRAGMA user_version`) не равна `DATA_VERSION` в `seed.py`. Так `start.bat` обновляет
старую `data.db`. **При любом изменении модели данных увеличивай `DATA_VERSION`.** Сейчас версия 2
(освоение тем и зависимости).
