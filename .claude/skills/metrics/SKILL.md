# Метрики

Все метрики считаются на бэкенде, фронт только отображает.

## Сложность темы (`analytics/difficulty.py`)

- `avg_score`: средний балл
- `fail_rate`: доля результатов с `score < 50`
- `difficulty_index = 0.6 × (1 − avg_score/100) + 0.4 × fail_rate`
- Уровень: `hard` при индексе ≥ 0.40, `medium` от 0.25 до 0.40, `easy` при индексе < 0.25
- `median_score`, `std_score`: медиана и выборочное стандартное отклонение балла
- `difficulty_z`: z-score индекса среди всех тем; `is_anomalous` при z ≥ 2

## Сравнение учебников (`analytics/textbooks.py`)

1. `z = (score − среднее)/std` внутри пары школа × тема
2. Усреднить z по ученику, чтобы два теста одного ученика не считались независимыми наблюдениями
3. Попарно: Welch t-test, поправка Холма на множественные сравнения, Cohen's d
4. Значимо при `p_adjusted < 0.05`
5. Эффект по |d|: < 0.2 пренебрежимо мал, 0.2–0.5 малый, 0.5–0.8 средний, ≥ 0.8 большой
6. Меньше 30 учеников у учебника: вывод не делаем, пишем «мало данных»
7. Без `topic_id` считаем по всем темам
8. Дополнительно к Welch: Mann-Whitney U с поправкой Холма (`mann_whitney_p_adjusted`), вывод `significant` от него не зависит
9. `ci_low`, `ci_high`: bootstrap 95% для разницы средних z (a − b), 2000 повторов, seed 42
10. `adjusted_score`: общее среднее + среднее отклонение результата от среднего «школа × тема».
    Это балл учебника, как если бы все учебники проходили в одинаковых школах. Разница в выводе
    (`conclusion`) считается по нему и подписана «в одних и тех же школах»
11. `confounding_note`: текст, если у какой-то пары сырая разница ≥ 2 балла и расходится с разницей
    `adjusted_score` на ≥ 2 балла. Из таких пар берём сначала незначимые, затем с наибольшим
    расхождением. Иначе `null`. На демо-данных: «без учёта школ C сильнее A на ~4 балла, в одной школе
    разница ~0 и не подтверждается»

Ограничение, которое нужно показывать честно: тест не учитывает группировку учеников
по классам, поэтому вывод опирается и на p-value, и на размер эффекта.

### Регрессия (`analytics/regression.py`, `GET /textbooks/regression`)

`score ~ учебник + школа + тема`, ошибки кластеризованы по классу, интервалы по t-распределению,
поправка Холма. Класс нельзя добавить фактором: у каждого класса один учебник, и вклады не разделяются.
Базовый учебник первый по алфавиту.

## Рекомендации по часам (`analytics/recommendations.py`)

- Получают часы `hard` и корни проблемы (см. ниже), отдают только `easy`, остальные `medium` не меняются
- Лимит изменения темы: `max(2, round(0.3 × часы))`
- Нужда `hard` пропорциональна сложности: цель = `max(часы + 1, округление_вверх_от_0,5(часы × difficulty_index / 0.40))`,
  нужда = `min(цель − часы, лимит)`. Тема в 1,4 раза сложнее границы получает в 1,4 раза больше часов
- По одному часу за шаг: получает `hard` с наибольшим `difficulty_index/часы`, пока не закрыта нужда,
  отдаёт `easy` с наименьшим; стоп, когда некому получать или отдавать
- Сумма часов сохраняется по построению
- **Корень проблемы** (`roots` из `/topics/prerequisites`) получает +1 час сверх своей нужды в пределах
  лимита: `hard` — `min(нужда + 1, лимит)`, `medium` — 1 час. Корни общие для общего плана и планов
  учебников; в плане учебника бонус есть, только если корень в этом плане `hard` или `medium`.
  В `reason`: «От неё зависят темы «Десятичные дроби» и «Проценты», поэтому ей нужен ещё час.»,
  у среднего корня «Тема средней сложности: … От неё зависит тема «Уравнения», поэтому рекомендуем
  добавить 1 час (7 → 8).» Получатель — только тема с нуждой > 0: донор с отрицательным изменением
  часы обратно не получает
- `reason`: понятный текст с цифрами, без обещаний роста баллов. `fail_rate` называется
  «не справились N% результатов» (это доля результатов, не учеников). Пример:
  «Тема сложная: средний балл 45 из 100, не справились 64% результатов. Она в 1,5 раза сложнее границы
  сложной темы, поэтому ей нужно около 7 часов вместо 5. Рекомендуем добавить 2 часа (5 → 7).»
- **По учебникам**: тот же расчёт отдельно на результатах классов каждого учебника, у каждого плана сумма 84.
  Баллы берутся с поправкой на школу: `балл − среднее школы по теме + среднее темы по всем школам`
  (та же логика, что `adjusted_score`, функция `adjust_for_school` в `textbooks.py`). Из них считаются
  `avg_score`, `fail_rate`, `difficulty_index` и уровень темы, поэтому средний балл учебника по теме совпадает
  с `adjusted_score` на странице «Учебники». Учебники сравниваются так, будто они проходят в одинаковых школах:
  это вклад учебника, а не состав его школ. Общий план «Все классы» считается по сырым баллам.
  `GET /recommendations` добавляет в каждый элемент `by_textbook` (textbook, level, avg_score, fail_rate,
  difficulty_index, hours_recommended, delta, reason с префиксом «Учебник B. ») и на верхнем уровне
  `textbook_plans` (textbook, hours_moved, added, text). На демо-данных на «Дробях» у A и C поровну, у B часов больше всех (A 2, C 4, B 6: у C «Уравнения» чуть выше границы сложной темы, отсюда ещё и корень «Отрицательные числа»)
- `GET /recommendations/optimal`: те же ограничения, `linprog` максимизирует `Σ difficulty_index × изменение часов`.
  Основной способ остаётся жадным, на показе linprog не выделяем: ответ совпадает (и с корнями тоже).

## Корень проблемы (`analytics/prerequisites.py`, `GET /topics/prerequisites`)

Ищем темы, слабое освоение которых тянет за собой провал следующих тем.

1. Матрица «ученик × тема»: средний балл ученика по двум тестам темы, только ученики со всеми темами
2. Общий уровень ученика: модель с одним общим фактором на ковариации тем `S`. Вклад уровня в тему
   `λ_t = √median_{j<k; j,k≠t}(S_tj · S_tk / S_jk)` (медиана: одна-две прямые связи не попадают в уровень).
   Ковариация остатков `U = S − λλᵀ`, диагональ не ниже 1% дисперсии темы
3. Для каждой темы t регрессия её остатка на остатки всех тем раньше по программе (`topic_id < t`) по `U`:
   `β = U[E,E]⁻¹ U[E,t]`, `se = √(diag(U[E,E]⁻¹) · σ²/n)`, p по нормальному распределению,
   поправка Холма по всем 66 парам. Стандартизованный коэффициент `β · √(U_ss/U_tt)`
4. Связь «ранняя → поздняя» при `p_adjusted < 0.05` и стандартизованном коэффициенте ≥ 0.15
5. Текст связи из `β` в баллах: «Ученики, которые написали «Дроби» на 10 баллов хуже, чем ученики их уровня,
   пишут «Проценты» в среднем на 2,5 балла хуже.» (`points = 10 · β`)
6. Корень проблемы — `hard` или `medium` тема, от которой зависит хотя бы одна `hard`. Текст ведёт от сложной
   темы к корню: «Тема «Проценты» сложная, но корень — тема «Дроби»: пробелы в ней переходят в «Десятичные дроби»
   и «Проценты». Сама тема «Дроби» тоже сложная.» У среднего корня: «Сама она средней сложности, и по её
   баллам проблему легко не заметить.»
7. Меньше 3 тем или 50 учеников: связей нет, «Мало данных, чтобы искать связи между темами.»

Почему не «балл минус прогноз по среднему за остальные темы»: при 12 темах такие остатки почти линейно
зависимы (их сумма по ученику ≈ 0), и регрессия на ранние остатки даёт ложные отрицательные коэффициенты;
а контроль средним по остальным темам оставляет у всех пар общий остаток уровня, и без зависимостей
появляются ложные связи. Почему не «во сколько раз чаще не справляются» по 5 группам уровня: внутри группы
уровень всё равно разный, и у пар без связи это отношение тоже ≈ 1,45. Цифра в баллах у таких пар ≈ 0.

На демо-данных ровно три связи: «Дроби → Десятичные дроби» (2,7 балла), «Дроби → Проценты» (2,5),
«Отрицательные числа → Уравнения» (3,4); корни «Дроби» и «Отрицательные числа». На данных без
зависимостей (`generate(..., prerequisites={})`) связей нет.

## LLM-пояснения (`analytics/explain.py`, `GET /recommendations/explanation`)

Один запрос к Claude (`claude-opus-5-5`, структурированный ответ) переписывает `reason` простым языком.
В запрос идут только агрегаты по темам и `by_textbook` (textbook, level, avg_score, fail_rate, delta). Числа только из исходных данных, без обещаний роста баллов.
При ошибке API, отказе модели или неполном ответе поле `source = template`, а `explanation` равно `reason`.
Удачный ответ кэшируется на время работы процесса, неудачи не кэшируются.

## Связь часов и результата (`analytics/hours_effect.py`, `GET /hours/effect`)

Спирмен и `средний балл ~ часы` по темам, минимум 3 темы. В ответе всегда есть `caveat`:
наклон не является приростом балла от часа, и в `reason` он не попадает.

## Кластеры (`analytics/clusters.py`, `GET /clusters`)

- Темы: K-means, k = 3, стандартизованные средний балл, доля несдавших, std; `random_state = 42`
- Школы: Ward, 2 кластера, профиль средних баллов по темам
- Группы именуются по среднему баллу

## Выбросы (`analytics/outliers.py`, `GET /classes/outliers`)

Ищем пары «класс × тема». Ожидаемый балл = уровень класса + сложность темы для его учебника
(взвешенный МНК по средним ячеек, школа входит в уровень класса). Отклонение = средний балл − ожидаемый,
робастный z = `0.6745 × (x − медиана)/MAD`, выброс при |z| ≥ 3.5. Найденная ячейка тянет оценки соседей,
поэтому по одной исключаем самую крайнюю и пересчитываем (до 10 раз). Меньше 3 тем: вывод не делаем.
Сдвиг класса сразу по всем темам не ищем: при ~25 учениках разброс уровня классов около 3 баллов,
и его нельзя отличить от аномалии. На демо-данных находится 6Д Школы №4, «Отрицательные числа».

## Качество заданий (`analytics/items.py`, `GET /items/quality?topic_id=`)

- Point-biserial: ответ на задание ↔ сумма остальных заданий того же теста
- `issue`: «слишком лёгкое» при доле верных ≥ 0.9, «слишком трудное» при < 0.1,
  иначе «не различает сильных и слабых» при r < 0.2. `is_bad` только для последнего:
  у крайних по трудности заданий r низкий из-за потолка, а не из-за формулировки
- Модель Раша: совместное максимальное правдоподобие, сложности центрированы, поправка `(L − 1)/L`.
  Ученики и задания без ошибок или без верных ответов исключаются

## Тренды (`analytics/trends.py`, `GET /topics/trends`)

По каждой теме `средний балл ~ год + школа` (архив плюс текущий год), поправка Холма по темам.
`ухудшается` или `улучшается` только при `p_adjusted < 0.05`, иначе `без заметных изменений`.

## PSM (`analytics/matching.py`, `GET /textbooks/matching`)

Логистическая регрессия учебника по входному тесту и школе, подбор 1:1 без возвращения,
caliper `0.2 × SD логита`. На подобранных парах парный t-тест по z и поправка Холма.
Меньше 30 пар: вывод не делаем. Баланс показываем как SMD до и после подбора.
В демо-данных сильные школы чаще выбирают C, и PSM вместе с регрессией снимают это смешение.

## Формат API

Числа в примерах иллюстративные.

`GET /topics/difficulty`

```json
[{"topic_id": 3, "topic": "Дроби", "hours_planned": 5, "avg_score": 51.8, "fail_rate": 0.44,
  "difficulty_index": 0.47, "level": "hard",
  "by_school": [{"school_id": 1, "school": "Школа №1", "avg_score": 49.2}]}]
```

`GET /textbooks/compare?topic_id=3`

```json
{"topic_id": 3, "topic": "Дроби",
 "textbooks": [{"textbook_id": 2, "name": "Учебник B", "n_students": 168, "avg_score": 46.1,
                "adjusted_score": 47.0, "mean_z": -0.42}],
 "comparisons": [{"a": "Учебник A", "b": "Учебник B", "p_value": 0.0001, "p_adjusted": 0.0003,
                  "cohens_d": 0.62, "effect": "средний", "significant": true}],
 "conclusion": "текст на русском", "confounding_note": "текст или null"}
```

`GET /topics/prerequisites`

```json
{"topics": [{"topic_id": 1, "topic": "Натуральные числа", "level": "easy"}],
 "links": [{"from_topic_id": 3, "from_topic": "Дроби", "to_topic_id": 5, "to_topic": "Проценты",
            "coef": 0.25, "std_coef": 0.207, "p_value": 1e-06, "p_adjusted": 6.6e-05, "points": 2.5,
            "text": "Ученики, которые написали «Дроби» на 10 баллов хуже, …"}],
 "roots": [{"topic_id": 3, "topic": "Дроби", "level": "hard",
            "dependents": [{"topic_id": 5, "topic": "Проценты", "level": "hard"}],
            "text": "Тема «Проценты» сложная, но корень — тема «Дроби»: …"}],
 "n_students": 550, "conclusion": "текст на русском", "note": "текст на русском"}
```

`topics` в порядке программы, `links` по порядку темы-основы.

`GET /recommendations`

```json

 "items": [{"topic_id": 3, "topic": "Дроби", "level": "hard", "hours_current": 5,
            "hours_recommended": 6, "delta": 1, "reason": "текст на русском",
            "by_textbook": [{"textbook": "Учебник B", "level": "hard", "avg_score": 46.6, "fail_rate": 0.60,
                             "difficulty_index": 0.562, "hours_recommended": 7, "delta": 2, "reason": "Учебник B. …"}]}],
 "textbook_plans": [{"textbook": "Учебник B", "hours_moved": 4, "added": [{"topic_id": 3, "topic": "Дроби", "delta": 2}],
                     "text": "Учебник B: добавить часы на «Дроби» +2, …"}]}
```
